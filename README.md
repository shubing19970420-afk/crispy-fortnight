# 一杆归洞 · 微缩世界

三关 2.5D 低多边形卡通高尔夫解谜原型。Three.js / WebGL + TypeScript + Vite，无后端、无运行时 CDN。全部模型、标记与音效由程序原创生成。

## 下载与试玩

GitHub 分支：`game/one-shot-golf-prototype`。打开该分支后点击 **Code → Download ZIP** 并解压。

安装 Node.js 22.12+（或 20.19+），在项目文件夹打开终端：

```sh
npm ci
npm run dev
```

浏览器打开终端的 Local 地址，通常为 `http://localhost:5173/`，保持终端开启。不要直接双击 HTML。手机和电脑在同一局域网时可访问 Network 地址。

使用支持 WebGL 2 的现代 Chrome、Edge、Firefox 或 Safari；浏览器需要允许硬件加速。无法初始化 WebGL 时游戏会显示说明和重新加载按钮。

## 玩法

- 首页「开始游戏」进入第一关；也可选择三个微缩预览进入指定关卡。
- 按住白球向后拖拽，松手发射。鼠标与触屏均可。橙箭头指向发射方向，白点预测最初约 0.26 秒，不显示完整路线。
- 拖拽达到 150 球场单位为最大力度；小于 6 单位取消击球。
- 每次挑战只有一次击球。滚动时不能再击球，停在洞外失败，可立即重试。
- **本版规则调整：球的中心轨迹进入半径 16 单位的有效洞口即成功，不要求低速或停在中心。** 连续线段检测避免高速漏判。捕获即冻结物理，随后播放约 0.65 秒吸入、下沉和缩小动画，再显示通关面板。
- 四边都是实体边墙。装饰在边墙或桌外延伸架上，不占用可通行球道。正常三关没有开放出界口，异常越界仍判失败。
- R 重试，Esc 返回选关；右上角开关音效。首玩教程、通关与音效偏好仅存在当前浏览器，禁用存储也能玩。

## 技术结构

| 文件                    | 职责                                                                           |
| ----------------------- | ------------------------------------------------------------------------------ |
| `src/levels.ts`         | 三关原始二维坐标与碰撞矩形，仍保持原布局                                       |
| `src/physics.ts`        | 240Hz 固定步长、惯性阻力、反弹、单次输入状态与连续入洞检测                     |
| `src/scene.ts`          | Three.js 正交相机、程序化模型、灯光/阴影、滚动、捕获、彩纸、短程预测与射线转换 |
| `src/main.ts`           | 首页、选关、指针/触摸输入、固定步长调度、教程、结果与本地进度                  |
| `src/audio.ts`          | Web Audio 合成击球、木质碰撞、橡皮碰撞、进洞声音                               |
| `src/style.css`         | 游戏 Logo、卡通按钮、力度表、教程与响应式 HUD                                  |
| `public/favicon.svg`    | 原创球洞图标                                                                   |
| `tests/physics.test.ts` | 三关解搜索、捕获与物理回归                                                     |
| `tests/browser.mjs`     | 真实 Chromium 操作与画面/模型验证                                              |

坐标映射固定为 `(x - 450, height, y - 280)`，一个物理单位等于一个场景单位。相机斜俯视约 40°，视角固定，窗口改变时自动适配整座球场。输入通过相机射线与球心高度水平面相交，将屏幕拖拽转换回二维物理方向和力度。

地面使用带洞的挤出几何体，洞口内壁和底部可见；障碍模型读取同一份矩形坐标。木墙和笔记本具有矩形完整外包层；六棱柱铅笔包含实体木托底座，与原矩形碰撞体一致；橡皮的圆角主体位于完整矩形底层上。装饰不会暗中增加碰撞体。

单方向柔和阴影、半球光、低面数模型与径向接触阴影提供接地感；未使用昂贵的屏幕空间 SSAO 后处理。像素比封顶 1.75，单张 1024² 阴影贴图，成功彩纸上限 34 个；切关释放模型、材质与标签纹理。浏览器回归使用软件 WebGL，不能作为实体中低端手机帧率结论。

## 检查

```sh
npm test
npm run build
```

浏览器回归需要已安装 Chromium：

```sh
# 终端一
npm run dev

# 终端二
npm run test:browser
```

默认 Chromium 路径为 `/usr/bin/chromium`，其他位置通过 `CHROMIUM_PATH` 指定。浏览器测试先运行物理测试生成 `/tmp/golf-solutions.json`，然后验证三关真实拖拽通关、投影往返、实际模型包围盒与碰撞体对应、下一关、失败/重试、取消拖拽、音效偏好、真实触摸事件、重复切关资源释放及 WebGL 不可用提示。截图写入忽略的 `test-results/`。

```sh
npm run build
npm run preview
```

`dist/` 为可部署的静态站点；通过 HTTP 服务访问。Three.js 引擎使主 JavaScript 包超过 Vite 默认 500KB 提示阈值，构建仍成功；实际下载可由服务器 gzip 压缩。当前开发环境的端口监听 `0.0.0.0`。

## 范围与后续

当前只做三关，首次体验约 5–10 分钟，**尚未达到最终作业 30 分钟以上**的要求。第三关用桌面、铅笔、橡皮和笔记本表达日常空间变成球场；布局与素材均原创，没有复制参考作品的模型或关卡。

本轮保持二维物理，三维只表现视觉，不含自由镜头、移动障碍、道具或其他玩法机制。实体 iOS/Android 手机触感、音效听感与中低端 GPU 性能仍需人工试玩确认。作业最终截止为 10 月 19 日 23:59；后续扩关应先记录实际试玩时长，再调整数量与节奏。

开发解（球场单位，仅调试参考）：第一关向右拖拽反方向约 55.6 单位；第二关从球向左下拖 `(47.005, 62.245)`；第三关向左下拖 `(53.320, 68.873)`。第二、三关均可一次墙面反弹入洞。
